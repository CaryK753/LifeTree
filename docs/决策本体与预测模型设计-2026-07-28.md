# LifeTree 决策本体与预测模型设计

- 日期：2026-07-28
- 作者：wwj
- 状态：第一阶段已实施

## 目标

LifeTree 的知识图谱不应只是节点可视化，而应成为决策运行时。每个结论都要能回答：依据是什么、通过哪些关系影响目标、可信度多少、现在能采取什么动作。

## 操作型本体

核心对象：

- `Goal`：用户希望达到的结果和目标日期。
- `Pathway`：通往目标的候选路径及状态。
- `Requirement`：路径共同需要满足的条件。
- `RiskFactor`：可能降低路径可行性的风险。
- `Event` / `InformationSource`：观察事实及来源。
- `Scenario`：一组可比较、可复现的假设。
- `Action`：能改变要求状态或风险暴露的用户操作，下一阶段实体化。

关系至少应包含 `weight`、`confidence`、`source_id`、有效期和场景归属。第一阶段已让 PostgreSQL `Relationship` 的权重、置信度和来源进入预测证据，并修正 Neo4j `AFFECTS` 关系属性。

## 推演语义

模型版本：`structured-scenario-v2`。

1. Requirement 采用加权几何准备度。重复添加相同要求不会提高成功率，缺失的高权重要求会形成明显拖累。
2. RiskFactor 采用生存项聚合，并对“风险完全独立”的不现实假设做相关性折减。增加风险不会提高成功率。
3. Monte Carlo 使用 Beta 分布表达输入不确定性。证据质量提高时分布收窄，但不自动改变方向或制造乐观均值。
4. 输出保留 `p10/p50/p90`，同时公开模型版本、假设、证据摘要和图谱路径。

## 决策路径

一次推演会构建以下解释链：

```text
InformationSource -> Relationship -> Requirement/RiskFactor
                  -> Pathway -> Goal -> ScenarioRun
```

每个因素输出：

- `evidence_quality`：关系置信度、信源可信度和时效性的组合。
- `evidence_count`：直接证据路径数量。
- `graph_paths`：可供 UI 下钻的来源与关系。
- `why_it_matters`：该因素是否已有来源支撑。

## 下一阶段

1. 将 `Action`、责任人、截止日期和执行状态加入本体，让建议可以直接转为任务并回写结果。
2. 为关系增加 `valid_from/valid_to`、冲突关系和人工确认状态，避免过期政策继续传播。
3. 将风险筛选从地区启发式升级为“与当前路径存在有效影响边”，无关系数据时才回退到地区规则。
4. 保存每次预测的输入特征和最终真实结果，计算 Brier Score、可靠性曲线与分组校准。
5. 在前端把因素列表升级为“证据 -> 因果边 -> 目标影响 -> 可执行动作”的决策工作台。

## 边界

当前输出用于情景比较和发现盲点，不是法律、医疗、财务、移民等专业意见，也不是对未来结果的保证。没有真实结果回流前，不应宣称模型已经完成统计校准。
